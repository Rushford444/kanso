# Portability

Emitted file and diagnostic paths retain the caller's input spelling. For a directory input, discovered child names use their on-disk spelling; the supplied directory prefix keeps its spelling and case. An explicit file, including a symbolic link to a file, retains the supplied path. Equivalent inputs are deduplicated by filesystem identity, and the first input that contributes an item supplies its spelling. If no input is supplied, the operating system's current directory is used; it may differ from the shell's logical working directory.

Symbolic links to files are followed only when their targets are within the project root. Symbolic links to directories are not followed when supplied without a trailing separator or discovered during traversal. A trailing separator may cause the operating system to resolve a directory link before discovery.

On macOS `/var` may resolve to `/private/var`. On Windows, canonicalization may return a long path in verbatim `\\?\` syntax with filesystem casing. Canonical paths identify files and roots internally; they are not used to replace caller spelling. Directory discovery joins the relative suffix to the caller's root, preserving the case and any 8.3 spelling in that prefix. Identity is not derived by lowercasing or stripping a prefix. For example, a caller prefix `C:\Accounts\RUNNER~1` stays unchanged in text and JSON paths.

SARIF converts Windows drive, UNC and verbatim paths to `file:` URIs and percent-encodes URI components. For example, `C:\Accounts\RUNNER~1\AGENTS.md` becomes `file:///C:/Accounts/RUNNER~1/AGENTS.md`. Text and JSON paths retain the caller spelling. Native Windows and macOS behavior depends on filesystem semantics.

Unix tests cover FIFO, Unix socket, device, symlink and permissions behavior. Unix reads use nonblocking and no-follow flags; other platforms do not provide those flags through this implementation. Windows has a `symlink_file` test; it skips only when Windows reports missing symlink privilege (error 1314). Windows has no equivalent FIFO or device fixtures here. Windows GNU cross-clippy checks compilation and lints, not runtime behavior. Native macOS and Windows tests remain necessary in CI; they have not been run as part of this release preparation.

## Filesystem test inventory

- `tests/io_hardening.rs`: `discovery_rejects_missing_input` runs everywhere. `discovery_records_non_not_found_input_error` checks Unix `ENOTDIR` and discovery's non-`NotFound` branch; `discovery_treats_child_of_file_as_not_found_on_windows` checks the Windows `NotFound` result. Windows maps `ERROR_PATH_NOT_FOUND` differently, so the same assertion cannot cover both. `m3_unreadable_file_reports_permission_denied` uses Unix mode bits and skips when the current user can still read mode 000.
- `tests/io_hardening.rs`: `m3_explicit_symlink_loop_is_diagnostic_not_fatal`, `m3_discovered_instruction_symlink_is_reported`, and `m2_reader_refuses_symlink_and_fifo` use Unix symlinks or `mkfifo` and are Unix-only.
- `tests/cli.rs` `fix_refuses_explicit_symlink_write`, `tests/cli_v012.rs` `local_instruction_alias_does_not_change_score_or_exit_code` and `relative_alias_works_for_all_commands`, and `tests/cli_v013_alias.rs` `alias_is_in_json_but_not_sarif_without_affecting_score_or_exit` use Unix symlinks and are Unix-only. `tests/cli_v012.rs` `fifo_has_explicit_non_regular_diagnostic` uses `mkfifo` and is Unix-only.
- `tests/caller_paths.rs` (all three tests), `tests/caller_paths_r2.rs` (the `unix` module: `broken_input_does_not_change_other_spelling`, `broken_relative_input_never_contaminates_other_inputs`, `terminal_symlink_uses_input_but_resolves_links_at_target`, `explicit_fifo_and_directory_are_one_failure`, `explicit_alias_and_walk_report_alias_once`) and `tests/caller_paths_r3.rs` (all five tests) are Unix-only because they create symlinks; `explicit_fifo_and_directory_are_one_failure` also creates a FIFO. The separate `regular_inputs_keep_first_spelling` test is portable.
- `tests/io_aliases.rs`: `aliases_are_read_once_and_bad_links_and_fifo_are_errors`, `discovered_fifo_is_a_not_regular_file_error`, `directory_ancestor_alias_preserves_special_file_diagnostic_paths`, and `equivalent_directory_inputs_deduplicate_discovery_failures` use Unix symlinks, FIFO or Unix sockets and are Unix-only. `directory_ancestor_alias_preserves_special_file_diagnostic_paths` also checks `/dev/null`, a Unix device, as a non-regular file. `windows_file_symlink_is_reported_as_an_alias` is Windows-only and skips only for privilege error 1314. `supported_directory_input_preserves_exact_path` uses a directory named like a file, not a file as a directory, and runs everywhere.
- `tests/cli.rs` `sarif_without_input_uses_os_current_dir_and_help_describes_options` runs everywhere, with a Windows-only inline assertion for the drive colon in the SARIF file URI.
- `tests/rule_hardening.rs` `fifo_anchor_never_blocks` and `device_anchor_never_reads_unbounded` use Unix `mkfifo`, symlinks and `/dev/zero` and are Unix-only. `tests/cli_v012.rs` `directory_named_as_instruction_is_traversal_failure` uses an ordinary directory and runs everywhere.
